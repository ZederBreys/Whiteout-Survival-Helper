# AUDIT_HERO_TABLE.md

## Исходная проблема

### Desktop (1440px)
- `table-layout: auto` — браузер распределял ширину пропорционально длине контента
- Колонка «Герой»: 200px (22%), при контенте ~130px → **70px пустоты**
- Колонка «Роль» (самая длинная): 355px (39%)
- Распределение: 200 / 99 / 106 / 156 / 355 px

### Mobile (375px)
- Карточный режим с `::before` label 140px — почти половина ширины карточки
- Hero name: 38px при 294px доступных → **256px пустоты в ячейке**
- `min-width: 0` + `flex-shrink: 1` сжимали имя до контентного минимума
- Большие вертикальные отступы (padding: 6px, gap: 8px)

## Первопричина

1. **Desktop**: `table-layout: auto` + отсутствие явных ширин колонок → браузер угадывает распределение на основе контента
2. **Mobile**: `min-width: 0` на flex-элементе имени героя → сжатие до контентного размера; label 140px → перерасход пространства

## Рассмотренные варианты

| Вариант | Desktop | Mobile |
|---|---|---|
| D1 | `table-layout: fixed` + colgroup | — |
| D2 | CSS Grid вместо table | — |
| M1 | — | Компактные карточки: label 110px, flex:1 на имени |
| M2 | — | Горизонтальный скролл + sticky первая колонка |
| M3 | — | Скрытие колонок на mobile |

## Выбранное решение: D1 + M1

**Почему:**
- D1 сохраняет семантику `<table>`, даёт точный контроль через `<colgroup>`
- M1 сохраняет все данные, читабелен на 320px, не требует скролла

## Итог

Таблица героев использует `table-layout: fixed` с двумя наборами ширин через `<colgroup>`: компактный для 768–1023px (170/70/65/130) и просторный для 1024px+ (180/80/70/140). Колонка «Роль» получает всё оставшееся пространство — от 246px на 1024px до 397px на 1440px+. Hero-ячейка: изображение 64px и имя центрированы, English name отдельной строкой. На mobile карточный layout оптимизирован: label 110px, имя через `flex: 1`, минимальные отступы. Поколения визуально разделены акцентной линией. Все данные доступны на всех разрешениях, горизонтальный overflow отсутствует.
