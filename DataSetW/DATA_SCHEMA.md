# DATA_SCHEMA.md

Контракт структуры данных.

Все объекты ниже — это то, что возвращает парсер после чтения DataSetW.
Описан в виде TypeScript-подобных интерфейсов для строгости, но в реальности
это обычные JavaScript-объекты, которые передаются в Eleventy.

---

## 1. Site

Корневой объект — весь сайт.

```ts
interface Site {
  /** Название сайта */
  title: string;

  /** Базовый URL (для canonical, sitemap) */
  baseUrl: string;

  /** Описание сайта (для meta description главной) */
  description: string;

  /** Все разделы верхнего уровня в порядке обхода папок */
  sections: Section[];

  /** Категория «События» — выделена отдельно для навигации */
  eventsCategory: Category | null;

  /** Общее количество .jpg/.png во всех разделах */
  totalImages: number;

  /** Общее количество .txt во всех разделах */
  totalTexts: number;
}
```

---

## 2. Section

Раздел верхнего уровня. Соответствует одной папке внутри DataSetW
(кроме подпапок «Информация по событиях» — они становятся Event).

```ts
interface Section {
  /** Уникальный идентификатор (slug) */
  id: string;

  /** Человеческое название (из имени папки) */
  title: string;

  /** Тип раздела */
  type: "section";

  /** Путь к исходной папке относительно DataSetW */
  sourcePath: string;

  /** URL страницы (начинается с /) */
  url: string;

  /** Группа для навигации */
  navGroup: "mechanics" | "development" | "guides" | "reference" | "other";

  /** Все изображения в разделе (может быть пустым) */
  images: ImageItem[];

  /** Пронумерованные изображения (1.jpg, 2.jpg...) */
  numberedImages: ImageItem[];

  /** Именованные изображения (Таблица по «Герои».jpg) */
  namedImages: ImageItem[];

  /** Контент раздела */
  content: SectionContent;

  /** Есть ли изображения */
  hasImages: boolean;

  /** Есть ли текст */
  hasText: boolean;

  /** Следующий раздел в порядке навигации (или null) */
  nextSection: string | null;

  /** Предыдущий раздел (или null) */
  prevSection: string | null;
}
```

---

## 3. Category

Папка, содержащая подпапки (Events). В DataSetW такая одна —
«Информация по событиях».

```ts
interface Category {
  /** Уникальный идентификатор */
  id: string;

  /** Человеческое название */
  title: string;

  /** Тип */
  type: "category";

  /** URL страницы-индекса категории */
  url: string;

  /** Подразделы (события) */
  children: Event[];
}
```

---

## 4. Event

Событие — подпапка внутри «Информация по событиях».
Отличается от Section: другой layout, хлебные крошки длиннее,
вложенность в URL.

```ts
interface Event {
  /** Уникальный идентификатор (slug) */
  id: string;

  /** Название события (из имени папки, без префикса) */
  title: string;

  /** Тип */
  type: "event";

  /** Полное имя папки (включая префикс "Информация по событию") */
  sourceFolderName: string;

  /** Путь к исходной папке */
  sourcePath: string;

  /** URL (включает префикс категории) */
  url: string;

  /** Родительская категория */
  parentId: string;

  /** Изображения (может быть пустым) */
  images: ImageItem[];

  /** Контент */
  content: SectionContent;

  /** Есть ли изображения */
  hasImages: boolean;

  /** Есть ли текст */
  hasText: boolean;

  /** Следующее событие */
  nextEvent: string | null;

  /** Предыдущее событие */
  prevEvent: string | null;
}
```

---

## 5. ImageItem

Одно изображение.

```ts
interface ImageItem {
  /** Имя файла (например, "1.jpg") */
  fileName: string;

  /** Полный путь к исходному файлу */
  sourcePath: string;

  /** Базовое имя без расширения ("1" или "Таблица по «Герои»") */
  baseName: string;

  /** Расширение: "jpg" или "png" */
  extension: "jpg" | "png";

  /** Номер, если имя числовое (1 для "1.jpg"), null если именованное */
  number: number | null;

  /** Является ли именованным (не числовым) */
  isNamed: boolean;

  /** Путь к обработанному изображению в dist (заполняется при билде) */
  outputPath: string | null;

  /** Размеры (заполняются @11ty/eleventy-img) */
  width: number | null;
  height: number | null;
}
```

## 6. SectionContent

Содержимое раздела — все тексты, структурированные по типам.

```ts
interface SectionContent {
  /** Тип организации контента (определяет шаблон) */
  layoutType: "single-image" | "multi-image" | "grouped" | "text-only";

  /** Все текстовые блоки раздела */
  blocks: ContentBlock[];
}

interface ContentBlock {
  /** Тип блока */
  type: "single" | "range" | "all" | "info" | "intro" | "extra" | "tip";

  /** Текст (Markdown-подобный, но фактически plain text с переносами) */
  text: string;

  /** Связанное изображение (для single) */
  image: ImageItem | null;

  /** Связанные изображения (для range или all) */
  images: ImageItem[];

  /** Порядок отображения (определяется парсером) */
  order: number;
}
```

---

## 7. Типы ContentBlock (детально)

### 7.1. type: "single"

Одно изображение → один текст.

Файлы: `Описание 1.jpg.txt`

```json
{
  "type": "single",
  "text": "Пещерная Гиена:\nУскоряет строительство на 5–15%",
  "image": { "fileName": "1.jpg", "number": 1, ... },
  "images": [],
  "order": 1
}
```

### 7.2. type: "range"

Диапазон изображений → один текст.

Файлы: `Описание для 2-3.jpg.txt`, `Описание 5-6.jpg.txt`,
        `Описание таблицы для 3-7.jpg.txt`

```json
{
  "type": "range",
  "text": "Данную расстановку лучше использовать после...",
  "image": null,
  "images": [
    { "fileName": "2.jpg", "number": 2, ... },
    { "fileName": "3.jpg", "number": 3, ... }
  ],
  "order": 2
}
```

### 7.3. type: "all"

Все изображения в разделе → один текст.

Файлы: `Описание всех .jpg.txt`, `Описание для всех .jpg.txt`

```json
{
  "type": "all",
  "text": "В начале игры нас интересуют данные персонажи...",
  "image": null,
  "images": [ /* все изображения раздела */ ],
  "order": 0
}
```

### 7.4. type: "info"

Общая информация раздела. Не привязана к изображениям.

Файлы: `Информация.txt`, `Информация N.txt` (несколько пронумерованных файлов)

`Информация.txt`:

```json
{
  "type": "info",
  "text": "Здесь можно увидеть бонус...",
  "image": null,
  "images": [],
  "order": 0
}
```

`Информация 1.txt` … `Информация 6.txt` — каждый файл становится отдельным
info-блоком, `order` берётся из номера в имени файла:

```json
{
  "type": "info",
  "text": "Для миграции нужен...",
  "image": null,
  "images": [],
  "order": 3
}
```

Пронумерованные файлы выводятся строго по порядку номеров независимо от
порядка чтения файловой системы.

### 7.5. type: "intro"

Вводная информация (показывается до изображений).

Файлы: `Информация в самом начале.txt`

```json
{
  "type": "intro",
  "text": "Поколение 1 (открывается с 55-го дня)",
  "image": null,
  "images": [],
  "order": -1
}
```

### 7.6. type: "extra"

Дополнительная информация (показывается после изображений).

Файлы: `Отдельное информация.txt`, `Отдельная информация после jpg.txt`

```json
{
  "type": "extra",
  "text": "Как развивать экспертов...",
  "image": null,
  "images": [],
  "order": 999
}
```

### 7.7. type: "tip"

Совет. Уникальный тип — только в папке «Советы».

Файлы: `Совет 1.txt`

```json
{
  "type": "tip",
  "text": "Золотые правила выживания...",
  "image": null,
  "images": [],
  "order": 0
}
```

## 8. Правила определения layoutType

Парсер определяет layoutType по составу content.blocks:

| Условие                              | layoutType      | Шаблон        |
|--------------------------------------|-----------------|---------------|
| Есть только info/intro/extra/tip     | `"text-only"`   | info-box      |
| Есть single-блоки (и только они)     | `"multi-image"` | image-block × N |
| Есть all-блок                        | `"single-image"`| текст + gallery |
| Есть range-блоки                     | `"grouped"`     | image-block × N (сгруппированные) |
| Смешанный (single + range + info)    | `"grouped"`     | по порядку order |

---

## 9. Порядок блоков (order)

Значения order определяют последовательность отображения:

```
order = -1   → intro (вводный блок, перед всем)
order = 0    → info, all, tip (общая информация)
order = 1..N → single, range (изображения с описаниями, по номерам)
order = 999  → extra (дополнительная информация, после всего)
```

Пронумерованные info-файлы (`Информация N.txt`) получают `order = N`
и выводятся между обычными info-блоками (order 0) и изображениями.

## 12. Краевые случаи (edge cases)

### 12.1. Изображение без описания

Пример: `Арена и Освоение/5.jpg` — файл существует, но ни одно описание
явно на него не ссылается (диапазон `Описание для 3-4.jpg.txt` покрывает
только 3 и 4).

Поведение парсера:
- Изображение попадает в `images[]` и `numberedImages[]`.
- Отображается в галерее без подписи.
- Валидатор выдаёт warning.

### 12.2. Изображение в нескольких описаниях (перекрытие)

Пример: `Арена и Освоение/3.jpg` — описано в обоих:
- `Описание для 2-3.jpg.txt` (range)
- `Описание для 3-4.jpg.txt` (range)

Поведение парсера:
- Оба блока сохраняются.
- Изображение отображается дважды: в группе 2-3 и в группе 3-4.
- Это осознанное поведение (соответствует структуре автора).

### 12.3. Именованные изображения без описаний

Пример: `Таблицы/Таблица по «Герои».jpg` — нет .txt.

Поведение парсера:
- Изображение попадает в `namedImages[]`.
- Отображается одиночно, без текста.
- Валидатор выдаёт warning.

### 12.4. Файл .txt неизвестного формата

Пример: `Советы/Совет 1.txt` — не соответствует стандартным шаблонам.

Поведение парсера:
- Тип определяется по эвристике: если имя содержит «Совет» → type "tip".
- Если совсем неизвестно → type "info" (безопасный fallback).

### 12.5. Нестандартный range (без «для»)

Пример: `Эксперты/Описание 5-6.jpg.txt` — нет предлога «для».

Поведение парсера:
- Регулярное выражение должно принимать оба варианта:
  `/^Описание\s+(для\s+)?(\d+)-(\d+)\.(jpg|png)\.txt$/`

### 12.6. «Отдельное» vs «Отдельная»

Примеры:
- `Научный центр/Отдельное информация.txt` (средний род)
- `Эксперты/Отдельная информация после jpg.txt` (женский род)

Поведение парсера:
- Оба варианта → type "extra".
- Регулярное выражение: `/^Отдельн(ое|ая)\s+информация.*\.txt$/`

### 12.7. Папка-категория без собственного текста

Пример: `Информация по событиях/` — нет Информация.txt на уровне категории.

Поведение парсера:
- Category создаётся, но без content-блоков.
- Страница категории рендерится как список дочерних событий.

### 12.8. Расширения: .jpg + .png в одной папке

Пример: `Таблицы/` — смесь `.jpg` и `.png`.

Поведение парсера:
- Оба формата обрабатываются одинаково.
- Именованные файлы с кириллицей и кавычками поддерживаются.
- @11ty/eleventy-img обрабатывает оба формата.

## 13. Инварианты (что никогда не меняется)

1. **DataSetW — единственный источник.** Парсер не создаёт и не изменяет
   файлы в DataSetW.
2. **Slug стабилен.** После создания slug не меняется.
   Меняется только если переименована папка.
3. **Порядок разделов** — как в файловой системе (алфавитный для русских имён).
4. **Текст не модифицируется.** Парсер читает .txt как есть.
   Никакой обработки Markdown,HTML-эскейпинг — задача шаблона.
5. **Отсутствие файла не ломает сборку.** Только warning.

---

## 14. Расширяемость

При появлении новых типов контента:

1. Добавить новый `type` в `ContentBlock`.
2. Добавить регулярное выражение в парсер.
3. Добавить обработку в шаблон (новый partial или условие).
4. Обновить этот документ.

Не нужно:
- Менять структуру Section/Event.
- Менять формат хранения в DataSetW.
- Переписывать существующий парсер.
